# 从瓶颈构造问题与验证系统

这是按需使用的研究思考工具，不是创新保证，也不是每个候选必须填写的新日志。与field-discovery的地图、opportunities的候选卡共用产物；研究者资源和贡献偏好可在brief记录，不能把某人的工程路线变成所有项目的规则。

## 先解释问题，再提出设计

用短链条解释：要解释的现象 → 中间过程/可观察变量 → 主要解释及成立条件 → 已解决的部分 → 有后果且尚不确定的部分。先读经典任务定义，不能只用近期方法倒推问题。用同一个具体事件比较两条路线如何判断、各自看到什么、何时会失败；教学例子标明假设，不能写成实测。

由地图中的共同假设或有定位的异常出发，沿“条件失效 → 缺失的变量/表示/观测 → 可以改变的设计 → 不同预测 → 判别 → 获得什么知识”构造候选。任务、表示、观测、数据、评测、机制都可以改变，但不是六种配额。每个候选要说清即使没有提升也可能学到什么；仅加入模块、换数据名或在新场景复测，不自动构成知识增量。
工程约束（同步、噪声、返工、成本、部署等）可成为有证据的失效条件；先问为何成熟方案失效、何种针对性改变能获得可推广到明确边界的知识。明确瓶颈或可论证的结构关系迁移才启用[transfer and engineering](transfer-and-engineering.md)，先近域再远域。它接回本节的设计/预测和已有候选卡，不另开一套流程；没有迁移依据时继续目标领域的简单/强路线。

去掉模型、模块和数据集名字后，如果两个候选仍问同一个问题、依赖同一证据并作相同预测，就合并或解释真正不同的条件。实验单位、目标真值及验证系统一起设计：可用原数据、合法受控子集、模拟或理论例子，但必须说清保留了什么机制、牺牲了什么真实性、结论不能外推到哪里。小验证系统不能冒充真实部署能力。

## 资源探查与科学判别分别写

资源探查回答能否取得材料、标签是否适配、试标是否可执行；它可决定停放，但成功本身不证明研究主张。
科学判别回答哪种解释更符合现象：至少列首选与最强替代解释、预测分叉条件、合法操作/观察、同信息的简单与强基线、指标和精度限制。把结果映射为支持哪种解释、反驳哪种解释、两者共存或不可区分，以及下一步如何改变判断。样本数与阈值未估计时说明如何估计，不以暂定数字制造确定性；观察无法区分就先修实验，而非直接堆复杂模型。

对重要候选先看科学判别是否值得做，再看验证系统是否可行；重要但暂不可行与可行但学不到东西分开排序。不能把访问许可未知写成ready。

## 最近似工作覆盖后只做一次有依据的重构

先明确近邻已解决的部分、成立条件和仍缺证据且有实际后果的未知。当前探索窗口允许一次有界修正：缩小主张、改变可检验条件或改贡献类型，并重新检索。修正必须由原文证据或明确假设推动；如果只是旧想法改名，或没有可区分的新知识问题，就淘汰/停放，不循环制造方向。以后出现实质新证据可按既有重开条件复核，不是永久禁止重构。
